# 《聆竹の休闲田园经济》Codex 分阶段制作索引

本目录把原《模组内容书》重组为 **16 个依赖有序的 Codex 开发批次**。使用方式：只把当前批次的 `.md` 文件交给 Codex；当前批次构建/验收通过后，再交下一批。不要一次性把全部批次都交给 Codex。

## 推荐工程基线

- Minecraft Java Edition 1.12.2
- Java 8
- Forge 1.12.2 Recommended 14.23.5.2859 MDK
- 后续批次默认是在前一批已经完成且可构建的同一个仓库继续修改。

## 顺序

1. **创建 Forge 1.12.2 模组工程与可扩展基础骨架** — `01_工程创建与基础骨架.md`  
   这是整个项目的起点。目标是得到一个干净、可构建、可启动的 Forge 1.12.2 模组工程，并提前建立后续系统共用的注册、网络、客户端/服务端分层与资源目录骨架。此批不实现经济玩法本身。
2. **建立玩家/世界持久化基础、首次初始化与金币 HUD** — `02_基础存档与金币HUD.md`  
   本批建立整个模组最重要的持久化底座：玩家独立数据、世界共享数据、首次世界初始化与金币账户。后续市场、商人和交通都必须复用这一套数据层。
3. **实现死亡以外的休闲化怪物行为与农田骚扰** — `03_休闲化生存规则.md`  
   本批只处理内容书第 3 节的生存规则：指定怪物不主动攻击玩家、苦力怕不破坏方块，以及低频农田骚扰。必须做到“只改指定关系”，不能把整个世界做成和平模式。
4. **实现世界日市场、冻结价格、趋势与历史数据底层** — `04_市场核心.md`  
   本批实现每日市场的服务端核心，不做商人交易 GUI。目标是任何商品都能基于世界日得到稳定的今日价格，并把作物历史行情持久保存。
5. **实现市场行情书物品、历史曲线 GUI 与网络同步** — `05_市场行情书.md`  
   在上一批 MarketService 基础上完成玩家可直接使用的市场行情书。此批完成物品、配方、14 种作物选择、历史曲线、悬停信息和跨维度显示。
6. **实现丰收、耕地行者、田园眷顾、精耕四个新增附魔** — `06_附魔农业组.md`  
   本批实现 8 个新增附魔中的农业/农场移动组。要求先把附魔注册、适用装备、等级、互斥和事件触发基础做稳定，再逐个实现精确效果。
7. **实现伐木、屠宰、捷足、夜视并完成八附魔原版体系集成** — `07_附魔工具战斗组.md`  
   本批完成剩余四种附魔，并把八种新增附魔正式接入附魔台、1.12.2 图书管理员随机附魔书与铁砧合并规则。
8. **实现旧版村庄识别、村庄交通站和商人实体生命周期** — `08_村庄与商人实体.md`  
   本批先建立村庄世界层与商人实体，不开放正式买卖。这样下一批交易系统可以依赖稳定的村庄 ID、交通站和商人归属。
9. **实现商人每日栏位、玩家出售、交易 GUI 与原子结算** — `09_商人交易核心与收购.md`  
   本批让商人真正可以收购玩家农业/畜牧产物，并完成 6 收购栏 + 10 出售栏的每日固定框架。出售给玩家的商品池先只建立框架，完整购买目录在后两批填充。
10. **填充商人普通/罕见购买目录、bundle 价格与库存** — `10_普通与罕见商品池.md`  
   本批把商人“玩家购买”侧的普通商品池和罕见商品池完整落地。所有条目必须数据驱动，禁止把几十项商品散落成 GUI if/else。
11. **填充稀有/珍宝/特殊附魔书并完成商人购买目录** — `11_稀有珍宝与附魔书.md`  
   本批完成商人购买侧剩余目录：稀有 2 条 + 珍宝 1 条，以及特殊附魔书候选。完成后商人的 10 条出售目录必须达到内容书的最终状态。
12. **实现蟹笼方块、20 槽容器、原版钓鱼等待与战利品** — `12_蟹笼核心.md`  
   本批先完成蟹笼的核心自动捕捞：方块/TileEntity/容器/GUI、工作环境、钓竿模块、等待时间和 1.12.2 钓鱼结果。生肉加速与漏斗自动化下一批再做。
13. **实现生肉饵料、漏斗输入输出与蟹笼最终联调** — `13_蟹笼饵料与自动化.md`  
   本批补齐蟹笼的生肉加速和原版漏斗自动化，使蟹笼达到内容书的最终功能状态。
14. **实现交通方块、自建站、接入费、移出/重激活与命名** — `14_交通节点基础.md`  
   本批完成玩家自建交通网络的节点层，不做实际远程传送与最近未解锁村庄。完成后玩家应能放置交通方块、建立/移出/重新激活节点、支付接入费并重命名。
15. **完成村庄线路解锁、最近未解锁村庄、安全传送与交通最终 GUI** — `15_交通旅行与村庄解锁.md`  
   本批把已完成的村庄站与玩家交通节点连接起来，完成付费解锁、旅行费用、安全落点和完整交通界面。
16. **多人持久化、防刷钱、平衡与全模组最终验收** — `16_最终联调与防刷验收.md`  
   这是收尾批次。不要再新增玩法；目标是把此前系统作为一个完整模组做多人、存档、重启、并发、防复制与冻结数值对照测试，修复发现的问题。

## 每轮操作建议

1. 确认上一批 `gradlew build` 已通过。
2. 只把当前批次文件交给 Codex。
3. 让 Codex直接修改当前仓库，不要让它重新创建第二个项目。
4. 检查 Codex 的完成汇报和构建结果；当前批未通过就继续修当前批，不要提前进入下一批。
5. 当前批通过后再进入下一份。

## 为什么这样拆

顺序遵循“工程骨架 → 持久化 → 独立玩法 → 市场 → 附魔 → 村庄/商人 → 商品目录 → 蟹笼 → 交通 → 最终联调”的依赖链。这样市场、交易、交通等高风险资产系统都建立在统一服务端数据层之上，减少后期推翻重写。
