# Codex 第 01 批：创建 Forge 1.12.2 模组工程与可扩展基础骨架

这是整个项目的起点。目标是得到一个干净、可构建、可启动的 Forge 1.12.2 模组工程，并提前建立后续系统共用的注册、网络、客户端/服务端分层与资源目录骨架。此批不实现经济玩法本身。

## 固定项目约束（本批次必须遵守）

- 游戏：Minecraft Java Edition 1.12.2。
- 模组名称：`聆竹の休闲田园经济`。
- 开发基线：Java 8；Minecraft Forge 1.12.2 Recommended `14.23.5.2859` MDK。
- 建议固定 `modid = lingzhu_farm_economy`，Java 根包名使用不冒充他人域名的自有命名；如果仓库已经有稳定 modid/package，则保持现有值，不要为了本任务重命名整个项目。
- 只能使用 1.12.2 存在的原版内容与 1.12.2 Forge API；禁止引入 1.13+ 的扁平化 ID、数据包、工作站/钟/袭击等后续机制。
- 所有金币、市场、库存、线路等关键资产必须由服务端权威处理；客户端只负责显示与发送请求，不能直接决定资产结果。
- 冻结数值不可擅自“平衡调整”、取整替换或简化。如果实现上遇到冲突，优先保持内容规则，并在最终汇报中说明实现取舍。
- 不要提前实现后续批次的完整功能；允许为了接口依赖创建最小占位类/接口，但不得把未要求系统一次性写完。
- 修改前先检查当前工程已有实现，复用已经完成的基础设施，禁止重复造第二套存档、网络、GUI 或注册系统。
- 完成后必须至少执行 `gradlew build`（Windows 可用 `gradlew.bat build`）并修复本批次引入的编译错误。

# 1. 模组定位

“聆竹の休闲田园经济”把 Java 1.12.2 的生存主循环调整为 **休闲种田 + 蟹笼捕捞 + 每日行情 + 商人 + 村庄交通 + 长期经营**。

玩家仍可正常挖矿、探索、进入下界与末地、挑战 Boss 和进行传统战斗；模组不删除这些原版玩法。但它们不再是获得关键资源的唯一途径。玩家可以主要依靠种植、养殖和其他可再生产物积累金币，再从商人处购买矿物、异界材料、结构战利品与收藏品。

## 1.1 核心循环

1. 种植并收获农作物、畜牧产物，或使用蟹笼进行被动捕捞。
2. 查看当天行情，寻找商人。
3. 出售商人当天收购的商品，获得金币。
4. 从商人当天出售的 10 项商品中购买所需资源。
5. 用资源扩建农场、建筑、仓储和红石自动化。
6. 发现村庄并付费接入交通网络，获得更多商人与每日商品选择。
7. 长期重复经营，不设置强制通关时限。

## 1.2 设计原则

| 原则 | 内容 |
|---|---|
| 轻松 | 世界首次启用模组时默认开启死亡保留物品；僵尸、骷髅、苦力怕、末影人、蜘蛛及其 Java 1.12.2 变种不会主动攻击玩家。 |
| 原版感 | 经济通过世界中的实体商人和交通站存在，不设置独立“市场建筑”或抽象商城。 |
| 种田可发展 | 农业收入可以替代大量挖矿、刷怪和结构探索的资源门槛。 |
| 沙盒自由 | 所有原版获取方式仍然保留，经济系统只是额外路径。 |
| 每日行情 | 商品每天涨跌，但同一世界同一天的价格固定，退出重进不能刷价。 |
| 长期存档 | 金币、交通线路、村庄交通节点、目的地名称、商人库存等长期保存。 |

## 1.3 明确不加入的系统

不加入农场等级、农场经验、任务/委托、随机经济事件、供需惩罚、季节、天气价格修正、战斗等级、商人营业时间、独立市场建筑或全局商城。

# 2. Java 1.12.2 版本边界

本内容书只使用 Java 1.12.2 已经存在的原版内容。1.12.2 仍属于 1.13“扁平化”之前的旧版内容体系，物品、方块与村庄内容均以 1.12.2 本身为准。

村庄也采用 1.12.2 的旧村庄时代：**没有钟作为村庄中心、没有村民工作站、没有 1.14 后的床/工作站/集合点村庄判定、没有袭击与掠夺者体系。**

本模组自己的“交通方块”“商人”“丰收”“耕地行者”属于新增内容，不受原版 1.12.2 是否存在同名内容限制。
