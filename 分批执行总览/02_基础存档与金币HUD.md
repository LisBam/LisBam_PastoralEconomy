# Codex 第 02 批：建立玩家/世界持久化基础、首次初始化与金币 HUD

本批建立整个模组最重要的持久化底座：玩家独立数据、世界共享数据、首次世界初始化与金币账户。后续市场、商人和交通都必须复用这一套数据层。

## 固定项目约束（本批次必须遵守）

- 游戏：Minecraft Java Edition 1.12.2。
- 模组名称：`聆竹の休闲田园经济`。
- 开发基线：Java 8；Minecraft Forge 1.12.2 Recommended `14.23.5.2859` MDK。
- 建议固定 `modid = lingzhu_farm_economy`，Java 根包名使用不冒充他人域名的自有命名；如果仓库已经有稳定 modid/package，则保持现有值，不要为了本任务重命名整个项目。
- 只能使用 1.12.2 存在的原版内容与 1.12.2 Forge API；禁止引入 1.13+ 的扁平化 ID、数据包、工作站/钟/袭击等后续机制。
- 所有金币、市场、库存、线路等关键资产必须由服务端权威处理；客户端只负责显示与发送请求，不能直接决定资产结果。
- 冻结数值不可擅自“平衡调整”、取整替换或简化。如果实现上遇到冲突，优先保持内容规则，并在最终汇报中说明实现取舍。
- 不要提前实现后续批次的完整功能；允许为了接口依赖创建最小占位类/接口，但不得把未要求系统一次性写完。
- 修改前先检查当前工程已有实现，复用已经完成的基础设施，禁止重复造第二套存档、网络、GUI 或注册系统。
- 完成后必须至少执行 `gradlew build`（Windows 可用 `gradlew.bat build`）并修复本批次引入的编译错误。

## 本批次必须实现

- 玩家持久化数据至少预留：金币、已解锁交通节点/线路、目的地别名、首个自建站免费资格是否已使用；本批实际启用金币字段，其余可做稳定序列化字段或扩展容器。
- 世界共享持久化数据预留：市场日与历史、村庄交通节点、商人当日商品/库存；本批可先建立版本化根数据结构，不实现业务刷新。
- 玩家新建/首次进入时金币为 0；死亡、切维度、退出重进、服务器重启后余额保持。
- 金币用足够大的整数类型保存；禁止负数和溢出回绕，不设置人为最高余额。
- 世界第一次启用本模组时，仅一次性把 `keepInventory` 打开；之后服主/玩家手动关闭时不得被模组持续改回。
- 客户端右上角显示金币 HUD：`金币 12,580` 风格，整数千位分隔；普通 HUD 隐藏时同步隐藏。
- 建立服务端向客户端同步金币的网络消息；所有余额修改 API 只能从服务端调用。
- 为后续交易准备原子式 `canAfford/addCoins/trySpend` 等统一接口，避免多个系统直接写 NBT。

# 3. 休闲化生存规则

## 3.1 死亡保留

- 一个世界第一次启用本模组时，默认把 `keepInventory` 设为开启。
- 只在首次初始化时设置一次，之后玩家或服主仍可自行关闭。
- 模组不会持续强行把该规则改回开启。

# 4. 金币系统

| 参数 | 数值/规则 |
|---|---|
| 货币名称 | 金币 |
| 初始金币 | 0 |
| 最低余额 | 0 |
| 最高余额 | 不设上限 |
| 是否有实体金币物品 | 否 |
| 显示位置 | 屏幕右上角 |
| 显示格式 | `金币 12,580`，整数、千位分隔 |

金币只是一种账户余额，不能丢在地上、装进箱子或被其他玩家捡走。

# 15. 多人、存档与防刷钱规则

## 15.1 多人数据归属

| 数据 | 归属 |
|---|---|
| 玩家金币 | 每名玩家独立 |
| 已解锁线路 | 每名玩家独立 |
| 目的地别名 | 每名玩家独立 |

| 拆村庄站复制 | 村庄站不作为普通可掉落方块 |
| 金币异常 | 不设置人为余额上限；余额不得出现负数，也不得因数值溢出出现清零、变负或异常回绕 |

## 验收标准

- 新玩家余额严格为 0。
- `/kill` 或正常死亡后金币不会丢失；切维度/重登/重启服务器后保持。
- 第一次启用模组的世界 `keepInventory=true`；手动关闭后重登不会被再次强开。
- HUD 位于右上角并能显示至少 0、999、1,000、12,580 等格式。
- 尝试扣除超过余额的金币会失败且余额不变；任何路径都不能得到负余额。
- 客户端不能通过伪造本地字段直接增加金币。

## 本批次明确不做

- 不实现市场价格生成。
- 不实现商人、交通、蟹笼或附魔。
- 不赠送交通方块，等交通方块正式完成后再接入首次赠送逻辑。
